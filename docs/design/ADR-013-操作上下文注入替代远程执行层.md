# ADR-013: 操作上下文注入替代远程执行层

日期：2026-09-26 · 状态：已接受 · 关联：ADR-011（远端执行通道，已退役）

## 背景

ADR-011 的 remote 层（executor.py 两跳包装 + sync.py JobSpec/tar-staging/push/pull 编排，
~380 行 + 46 测试）诞生于 Windows 开发机时代：本地无 NPU，须本地→jump→e15 两跳中转，
harness 代执行是唯一形态。

迁移到 jump（/data01/mahaolong/KAgent）后该前提消亡：harness 与 e15 只隔一跳裸 `ssh`。
同时用户裁定架构方向：**不新增远程执行层——把"如何访问 NPU"作为操作上下文注入各模块，
让 LLM 自行决定怎么访问**。这与 KDA-Pilot 的实证形态一致（契约告诉 agent 环境怎么用，
agent 自己 ssh 跑，评审查证据溯源），也更符合 agent 成熟度目标（自主性来自知情，不来自代劳）。

## 决策

1. **删除**：executor.py、sync.py 传输编排（JobSpec/run_job/push/pull/_build_exec_cmd）、
   smoke_remote_job.py 及其 46 项测试。
2. **保留**：runner.py（canonical 口径）、container_entry.sh、test_runner_offline.py。
3. **新增**：
   - `harness/context.py`——NPU 访问手册生成器（canonical 命令模板/payload 布局/冻结面 sha/
     自由调试许可与红线），注入 writer prompt + 落盘 tasks/<t>/docs/npu-access.md
   - writer 输出协议扩展 `===EXEC===` 块（与 ===CODE=== 同族解析）：LLM 自己写远端命令序列
   - `harness/control/exec_policy.py`——EXEC 块护栏（白名单前缀 + 账本/冻结面写入拒绝 +
     rm -rf/git 破坏拒绝）；违规→exec-policy-reject 审计 + 下轮反馈
   - loop 的 VERIFY/BENCH 阶段改为 exec_stage：LLM 脚本或 canonical 兜底 → bash -s 执行 →
     从 stdout 提取 results json → Evidence 落账；脚本落盘 run/round-N-exec.sh 供复盘
4. **CLI** verify/bench 重写为同一 canonical 模板的薄入口（人类/测试可桩）。

## 三条底线（不可让步）

| 底线 | 实现 |
|---|---|
| canonical runner 不可绕 | 出数口径唯一 = runner.py 的 results json；手册明示自建计时只可用于诊断叙述，进结论=REJECT |
| 测量纪律 harness 独占 | job.json（workload 双档/chained/sha）由 harness 生成，LLM 不许改写（EXEC 护栏拦 job.json 仓内写） |
| 账本唯一写方 | benchmark.csv/solutions.jsonl/audit.log 只有 Evidence 写；LLM 输出进 prompt 与 audit |

## 后果

- 净代码 -380 行、测试 -46+8（180→144：删 46 传输用例 + 新增 8 个 context/policy/EXEC 用例，
  原 P0/P1 用例全数保留）
- LLM 获得环境自主权（可加前置探针：compile 冒烟/TRITON_CACHE/单 workload 试跑/npu-smi），
  自主性从"被动等 harness 代跑"变为"知情自主操作"
- 风险：LLM 命令面扩大 → 由 exec_policy 白名单+黑名单矩阵约束；误操作远端 workspace →
  workspace 为任务隔离目录，污染面有限且 job/payload 每轮重建
- supervise.py 零改动（verify-step/bench-step 事件序列保留）
